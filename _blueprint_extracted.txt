Executive Summary
BioAgent-ST is proposed as a verification-first scientific agent for spatial transcriptomics. Rather than treating an
LLM as an unrestricted analyst that produces fluent biological narratives, the system is designed as a controlled
scientific workflow in which analysis tools execute deterministic computations, intermediate artifacts are recorded,
claims are evaluated against evidence, and uncertainty influences the system's behavior.
The central research question is whether active verification, structured uncertainty, and provenance constraints
can reduce unsupported biological assertions compared with strong tool-using baselines, particularly when data
are noisy, sparse, platform-shifted, statistically underpowered, or biologically ambiguous.
Core design principle
Verification is not a post-hoc safety layer. It is a first-class scientific capability that participates continuously in
planning, execution, interpretation, escalation, and reporting.
The project should be built in layers:
1
A deterministic scientific analysis layer built around AnnData, Scanpy, Squidpy, and statistical libraries.
2
A typed tool interface that exposes validated scientific operations instead of unrestricted arbitrary code
execution.
3
A stateful Planner–Executor workflow connected to a Verifier–Critic loop.
4
A live five-state evidence ledger for claim-level classification.
5
A provenance-native artifact system that records dataset hashes, code versions, parameters, random seeds, tool
versions, timestamps, and lineage.
6
An evaluation harness containing baseline comparisons, ablations, controlled degradation, auditability checks,
and expert or structured review.
This document combines the project context, recommended technology stack, architecture, data models, team
division, research methodology, implementation roadmap, risks, and paper-development guidance.
1. Research Identity and Scope
1.1 What BioAgent-ST is
BioAgent-ST is a research prototype for scientific analysis of spatial transcriptomics data. It receives a biological
research question and a dataset, constructs a constrained analysis plan, invokes validated computational tools,
evaluates intermediate evidence, and produces an auditable report.
1.2 What BioAgent-ST is not
●
It is not simply a chatbot that explains spatial transcriptomics.
●
It is not a replacement for Scanpy, Squidpy, or domain experts.
●
It is not a claim that an LLM can independently establish biological truth.
●
It is not initially a foundation-model training project.
●
It is not a production clinical decision system.

●
It should not be judged only by fluency, task completion, or the number of generated conclusions.
1.3 Research thesis
The proposed thesis is that scientific agents should be optimized not only for completing workflows, but also for
maintaining a defensible relationship between claims and executed evidence. Under degraded conditions, a
scientifically disciplined agent should become more cautious, expose uncertainty, request additional analysis, or
escalate to human review instead of preserving a confident narrative at all costs.
1.4 Research questions
1
Does the full BioAgent-ST configuration reduce the rate of unsupported biological claims compared with
tool-using baselines?
2
Does the system increase Indeterminate classifications and human-review escalations as data quality declines?
3
Do the evidence ledger, dual-loop critic, uncertainty gating, and provenance constraints each contribute
measurable value?
4
Can an independent researcher reconstruct key numerical results and decision points from the provenance
ledger alone?
5
Does the system preserve useful scientific task completion while becoming more cautious under uncertainty?
2. Positioning Against Existing Directions
The internal research brief situates BioAgent-ST relative to spatial and single-cell agentic systems including
SpatialAgent, STAT, STAgent, ChatSpatial, and CASSIA. The brief identifies overlapping capabilities in tool use,
interactive analysis, multimodal reasoning, schema enforcement, and annotation uncertainty.
The proposed distinction is not that existing systems lack all verification. Rather, BioAgent-ST emphasizes a
specific combination: an active dual-loop architecture, a five-state evidence ledger, uncertainty-gated autonomy,
and provenance-native generation. These are research hypotheses and design targets that must be checked
against the latest literature and implementations before being claimed as novel.

4.2 Why Python-first
A Python-first stack minimizes integration overhead because the scientific analysis, data structures, statistics,
evaluation harness, and orchestration can share one language. A separate Node.js backend is unnecessary for the
initial research prototype. A frontend can be added after the scientific workflow is stable.

●
A cluster is not automatically a validated cell type.
●
A marker association is not automatically causal evidence.
●
Spatial proximity is not automatically a biological interaction.
●
A statistically significant result is not automatically biologically important.

absence.

The agent must report limitations and assumptions for each analysis method.

6.3 Confidence versus evidence
An LLM's self-reported confidence is not equivalent to a calibrated statistical probability. The implementation
should separate categorical evidence state, statistical evidence, empirical calibration, and reasons for uncertainty.
A numerical confidence field may be stored, but it should not be interpreted as statistically meaningful until
calibrated and evaluated.

The first implementation should expose controlled scientific tools rather than allowing unrestricted Python
generation and execution. Typed tool interfaces improve validation, reproducibility, observability, and error

11.3 Controlled degradation
●
Technical noise or gene dropout.
●
Reduced cell or spot counts.
●

●
Low-replicate settings.
●
Biologically ambiguous questions.

Degradation experiments must be documented carefully. Synthetic perturbations should be justified, reproducible,
and distinguished from naturally occurring data-quality problems. The same scientific question should be evaluated
across a controlled degradation continuum.

Definition / purpose
Unsupported-claim rate
Fraction of evaluated biological assertions judged unsupported by independent review or a validated

Graceful-degradation response

Ability to complete valid scientific tasks when evidence is sufficient.
Human review quality
Structured judgments of trustworthiness, usefulness, and clarity from qualified reviewers.

18. Final Strategic Guidance
The strongest version of BioAgent-ST is not the one with the largest number of tools, the most complicated
multi-agent architecture, or the most visually impressive interface. It is the one that can make a precise scientific
claim about reliability and support that claim with controlled experiments.
For a two-person team, the recommended strategy is to build a narrow but rigorous vertical slice: one or two
datasets, three workflows, typed tools, a provenance layer, a five-state evidence ledger, and a minimal report
generator. Once that slice is reproducible, add the active critic, uncertainty gating, degradation experiments, and
baseline comparisons.
North-star principle
Build a system that knows what it executed, knows what evidence it has, distinguishes findings from
hypotheses, exposes uncertainty, and can be audited by someone who was not present during the run.
A publishable paper will depend on what the experiments demonstrate—not simply on the elegance of the
architecture. Treat every design decision as a hypothesis to test, every biological conclusion as evidence-bound,
and every limitation as part of the scientific contribution.

A.3 Report constraints
●
Every quantitative statement must reference an artifact or validated evidence record.
●
Every biological conclusion must have an evidence state.
●
Every uncertainty statement must identify its reason.
●
Unsupported or Indeterminate claims must not be silently rewritten as findings.
●
The report should list data, software, parameters, and limitations.
